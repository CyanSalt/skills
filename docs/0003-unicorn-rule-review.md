## Scope and evidence

This review covers the actual installed `eslint-plugin-unicorn@80.0.0`: 399 exported rule names, comprising 379 active rules and 20 deprecated rule entries. Of the active rules, 340 are enabled by the JavaScript recommended preset. Other supported languages use their corresponding presets. SOML-specific application is outside this Skill's scope. The [versioned rule catalog](https://raw.githubusercontent.com/sindresorhus/eslint-plugin-unicorn/v80.0.0/readme.md) and installed rule metadata are the inventory sources.

Every exported rule was screened by description and preset membership. Rules with likely framework, state, protocol, mutation, timing, or compatibility conflicts received targeted review of their version-matched documentation; this is a complete inventory screening, not a claim that every rule implementation or every documented example was exhaustively tested. The appendix records all exported names and distinguishes candidates, ordinary review findings, opt-in rules, and deprecated rules/aliases.

Twenty isolated ESLint probes confirmed selected reported and allowed cases. Separate runtime probes confirmed the Proxy/private-field brand-check incompatibility and the error-boundary difference between two-argument `then` and `then().catch()`. The actual Skill entry point initially passed 17 integration tests, including the module-state exception; the authorized follow-up passed 19 tests, adding framework/documentation preservation and narrowed function-scoping coverage. The current process uses Node 22.23.2; its `Iterator.zip` is unavailable. These are local observations, not a cross-browser or cross-version compatibility certification.

The recommendations below are review judgments. The initial review disabled only the requested module-state rule. A subsequent authorized configuration update also disabled `no-this-outside-of-class`, `no-null`, and `no-asterisk-prefix-in-documentation-comments`, and restricted `consistent-function-scoping` with `checkArrowFunctions: false`. The contract-dependent group beginning with `consistent-boolean-name` remains unchanged, as do the private-field and iterator-zip candidates. A rule marked `problem`, or omitted from `unopinionated`, is not by itself proof that a valid use case is wrong or that a rule should be disabled. `unopinionated` excludes useful correctness checks too, so it is not a drop-in substitute for this audit.

## Applied change

`unicorn/no-top-level-assignment-in-function` is disabled in the shared exception block, after the language presets. Intentional module-level counters, singleton handles, and lazy caches remain valid audit inputs. The rule checks binding reassignment but permits object property mutations, so mechanically wrapping a binding in an object would change the representation without establishing better state safety. Shared-state ownership, async interleaving, reentrancy, and reset behavior still need code review. [Rule documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-top-level-assignment-in-function.md).

The existing filename and framework-name exceptions are unchanged. The authorized follow-up allows framework receivers and explicit null values, preserves conventional documentation comments, and skips arrow-function scoping checks while retaining ordinary-function checks. The following section preserves the review rationale; the configuration and appendix distinguish applied overrides from remaining candidates.

## Highest-priority candidates

### `no-this-outside-of-class`: allow supported framework receivers

Vue Options API methods, ordinary object methods, and SDK callbacks can intentionally depend on an implicit `this`. The documentation explicitly says these patterns are unsupported by this intentionally strict rule; TypeScript functions with an explicit `this` parameter are allowed. Converting valid Vue options into classes just to satisfy lint would be an inappropriate framework migration. For an audit meant to support broad Vue/JavaScript usage, this is the strongest next disable candidate. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-this-outside-of-class.md).

### `no-null`: preserve protocol values

React refs often use `null` as an initial absence value; explicit `null` also distinguishes a cleared value from a missing property in JSON-facing contracts and library APIs. `checkArguments: false` only relaxes direct call arguments; it does not address object fields or state initializers. Strict equality checks already pass by default. For a cross-project audit, disable this rule or keep protocol-specific findings unresolved rather than replace `null` indiscriminately. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-null.md).

### `consistent-function-scoping`: preserve locality and function identity

A function can remain near its sole use even when it captures no outer variable. A factory may deliberately return a fresh callback identity on each invocation; hoisting the callback makes separate factory calls return the same function. Built-in React hooks and Jest/Vitest hoisted factories already have exclusions, so those examples do not justify an additional broad exemption. Custom factories and local helpers remain legitimate cases. Consider `checkArrowFunctions: false` as a narrower compromise, or disable if locality and fresh identity are regular design choices. There is no automatic fix. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/consistent-function-scoping.md).

### `no-asterisk-prefix-in-documentation-comments`: conventional documentation formatting

Conventional multiline JSDoc uses leading asterisks. This rule removes their prefixes and shared indentation; regular JavaScript block comments are ignored, while CSS and JSONC/JSON5 block comments are also affected. This is a formatting preference, not evidence of faulty documentation or runtime behavior. Disable when the repository's documentation style or formatter uses conventional prefixes; do not invent a mandatory rewrite of those comments. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-asterisk-prefix-in-documentation-comments.md).

### `prefer-private-class-fields`: avoid Proxy and reflection regressions

Underscore-prefixed members may be conventionally private but intentionally observable by serializers, subclass code, debugging tools, or Proxy-based state systems. Native private fields use brand checks and do not behave like ordinary properties. The documentation explicitly warns about Vue `reactive()` and MobX incompatibility and reflection patterns that the automatic fix cannot detect. Disable for reactive models, or retain only where native private-field semantics are actually desired. This candidate has a stronger behavior risk than a cosmetic naming rule. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/prefer-private-class-fields.md).

### `prefer-iterator-zip`: unsupported replacement at the current target

Parallel-array index loops are common and valid. This rule suggests `Iterator.zip`, but its versioned documentation states that the API is not shipped by the engines it discusses. The API is also absent in the local Node process. Disable for targets without support; revisit only after verifying the actual execution targets. Do not confuse availability of ordinary iterator helpers with availability of `zip`. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/prefer-iterator-zip.md).

## Use scoped configuration or manual review

- **`consistent-boolean-name`**: `enabled`, `loading`, `visible`, and `disabled` can be conventional state names. Use `checkVariables`, `checkArguments`, and `checkFunctions` set to `prohibit` to reject misleading prefixes without forcing a prefix onto every boolean. Fields/methods and destructured bindings are already skipped by default. Direct Vue refs/computed values and conventionally suffixed React refs have support; type-aware `wrappers` are unavailable in this parsing-only Skill. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/consistent-boolean-name.md).
- **`no-array-reduce`**: folds, custom accumulators, and functional code can be clear and linear when they mutate an owned accumulator rather than repeatedly copy it. Simple numeric operations already pass through `allowSimpleOperations: true`. Disable if functional folds are accepted; retain `no-array-concat-in-loop` and review accumulator-spread complexity separately. Do not infer that every reducer is quadratic. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-array-reduce.md).
- **`prefer-then-catch`**: `then(onFulfilled, onRejected)` may intentionally recover only from the original rejection while allowing a fulfillment-handler failure to propagate. `then().catch()` broadens that error boundary. The documentation acknowledges this and offers suggestions, not automatic fixes. Retain as a review prompt only if such intentional boundaries can remain unresolved; otherwise disable. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/prefer-then-catch.md).
- **`prefer-await`**: reusable promise pipelines and Cypress/custom `.then()` APIs can intentionally remain callback-based. The parsing-only mode relies on method-name heuristics; known non-promises need type information to be excluded reliably. `void` already opts out for fire-and-forget chains. Consider disabling in callback-based libraries or test suites rather than wrapping every chain in an async IIFE. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/prefer-await.md).
- **`prefer-event-target`**: existing Node APIs and SDKs may require EventEmitter semantics, multiple event arguments, special error handling, repeated listener registration, or methods absent from EventTarget. This is an API migration, not a safe naming substitution. Keep EventEmitter for that contract and disable in Node-specific code if the finding is recurrent. [Rule](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/prefer-event-target.md), [Node documentation](https://nodejs.org/api/events.html#nodejs-eventtarget-vs-dom-eventtarget).
- **`prefer-number-coercion`**: parsing a numeric prefix such as a CSS measurement intentionally differs from parsing the whole string with `Number`. No universal replacement preserves both contracts. Keep `parseFloat`/base-10 `parseInt` where prefix parsing is the intended API; disable if that is a regular use case. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/prefer-number-coercion.md).
- **`prefer-code-point`**: a UTF-16-based hash or code-unit protocol intentionally uses `charCodeAt`. Substituting `codePointAt` can change the algorithm and requires code-point iteration, not only renaming the method. Retain for human text handling, but scope out code-unit algorithms. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/prefer-code-point.md).
- **`prefer-dom-node-text-content`**: rendered text extraction can need `innerText`; textContent is not the same rendered-text operation. Review the read contract and keep the rule for contexts where raw text is desired. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/prefer-dom-node-text-content.md).
- **`require-array-sort-compare`**: deterministic code-unit ordering of strings may intentionally use default sort. `localeCompare` introduces a different ordering and can depend on locale. Prefer an explicit code-unit comparator if keeping this rule, or scope it out for those string lists; retain explicit numeric comparators and `no-boolean-sort-comparator`. No `allowStrings` option is documented for this Unicorn rule. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/require-array-sort-compare.md).
- **`no-global-object-property-assignment` / `no-top-level-side-effects`**: test-environment setup, polyfills, shims, and instrumentation can intentionally modify globals. Scope these out of setup/initialization files. Do not globally remove useful global-mutation warnings. `no-top-level-side-effects` allows ordinary unknown calls by default; it is not a blanket ban on module initialization. [Global mutation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-global-object-property-assignment.md), [module effects](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-top-level-side-effects.md).
- **`no-array-sort` / `no-array-reverse` / `no-array-splice` / `prefer-array-slice`**: mutable collections, reactive arrays, and alias-sensitive algorithms need identity-preserving updates. Standalone sort/reverse and many owned or escaping splice patterns already pass; review return-value chains before replacing mutating APIs. For splice, removed elements and the changed array are different return contracts. [Sort](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-array-sort.md), [reverse](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-array-reverse.md), [splice](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-array-splice.md), [slice](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/prefer-array-slice.md).
- **`prefer-https`**: HTTP-only compatibility tests, source samples, and protocol identifiers can intentionally contain HTTP URLs. The rule already allows localhost, private-looking hosts, reserved non-public suffixes, and selected XML identifiers. Use its exact URL or regular-expression `ignore` option for repeated intentional public-looking strings, rather than rewrite test inputs or disable secure transport advice globally. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/prefer-https.md).
- **`no-for-each`**: synchronous side-effect iteration is a common valid style. Sparse arrays and collection mutation require special care because `forEach` and `for...of` have different iteration contracts. Preserve those behaviors during review; do not equate this choice with unsafe async callbacks, which deserve their separate correctness check. Known Map/Set receivers are already excluded. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-for-each.md).
- **`no-new-array` / `prefer-spread`**: deliberate sparse arrays and array-like inputs are valid contracts. `new Array(length)` creates holes, unlike `Array.from({length})`; `Array.from(arrayLike)` accepts non-iterable array-like objects, unlike spread. Keep the original representation when holes, iterator absence, callback skipping, or alias behavior matter. These are review findings, not permission to convert every allocation or copy. [Sparse arrays](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-new-array.md), [spread](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/prefer-spread.md).
- **`no-single-promise-in-promise-methods`**: a one-item combinator can intentionally preserve an array-shaped result or an `AggregateError` rejection contract. The rule already leaves `allSettled` alone, but `any` remains a reported suggestion because direct awaiting changes its rejection shape. Preserve the established contract when callers depend on it. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-single-promise-in-promise-methods.md).
- **`no-computed-property-existence-check`**: a dictionary lookup may intentionally read a boolean value or test inherited membership. `Object.hasOwn` changes that contract. Type-aware boolean reads are recognized, but parsing-only mode cannot always establish them. Use explicit value comparison, a collection abstraction, or scoped suppression according to intent. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-computed-property-existence-check.md).
- **`no-incorrect-template-string-interpolation`**: generated source, URL templates, and other-language brace placeholders may intentionally contain `{name}`. Tagged templates and some code-generation syntax already pass. Review remaining literal placeholders and scope the rule out where needed. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-incorrect-template-string-interpolation.md).
- **`prefer-queue-microtask` / `no-unnecessary-await` / `prefer-array-from-async` / iterator-helper conversions**: scheduling, yield points, iterator closing, concurrent starts, callback arguments, and consumption order may be intentional. These transformations need semantic review even when a fix is available. Timer-to-microtask checks are off by default; ordinary async collection patterns should not be rewritten into sequential work accidentally. [Microtasks](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/prefer-queue-microtask.md), [await](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-unnecessary-await.md), [async arrays](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/prefer-array-from-async.md), [iterator helpers](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/prefer-iterator-helpers.md).

This Skill ignores source-level ESLint disable directives and uses its isolated configuration. Upstream advice to add a local disable comment does not suppress this audit. The scoped remedies above are possible configuration decisions for a future change, not already exposed user options. Until then, preserve incompatible code and report a concrete reason rather than rewrite behavior or pretend a comment fixes the finding.

## Common cases already allowed

- Standalone `array.sort(comparator)` and `array.reverse()` pass their respective rules by default. A comparator may still be required by the separate sort-comparator rule. [Sort](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-array-sort.md), [reverse](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-array-reverse.md).
- CommonJS `.cjs` and `.cts` are excluded by `prefer-module`. Nonstandard CommonJS JSX suffixes are not listed in that exception, so verify them separately. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/prefer-module.md).
- TypeScript module-marker `export {}` and declaration-file markers have documented exceptions. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/require-module-specifiers.md).
- Simple arithmetic reduce is allowed by default. General reducer patterns remain checked. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-array-reduce.md).
- Built-in React hooks and Jest/Vitest mock factories have function-scoping exclusions; they should not be used as evidence that every such callback is reported. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/consistent-function-scoping.md).
- Plain TODOs are allowed, and date expiry checks are disabled by default. The rule checks explicit conditions rather than requiring a deadline on every TODO. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/expiring-todo-comments.md).
- A single parenthesized nested ternary is allowed. The rule is not a total ban on nested conditional expressions. [Documentation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-nested-ternary.md).
- Labeled loop exits, same-current-entry Map/Set mutations, common router push chains, and unknown/public callers have documented exclusions in their respective rules. [Loop exits](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-break-in-nested-loop.md), [mutation](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-loop-iterable-mutation.md), [push](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-return-array-push.md), [parameters](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-unnecessary-parameters.md).
- `prefer-dom-node-html-methods` does not enforce `setHTML` assignments by default; `checkSetHTML` is false. `require-passive-events` and `prefer-observer-apis` are also narrower than their names suggest. Do not disable them solely on the assumption that they ban all scroll handlers or HTML assignments. [HTML methods](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/prefer-dom-node-html-methods.md), [passive listeners](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/require-passive-events.md), [observers](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/prefer-observer-apis.md).

## Stylistic choices and opt-in rules

Catch-variable naming, default export declaration style, class member order, conditional spread style, explicit length comparisons, nested-call limits, switch braces, encoding spelling, and literal casing may conflict with local style. They are lower-priority disable candidates: configure a preferred style where possible and avoid removing them without evidence of repeated friction. Class member reordering needs additional care because field initializers and static blocks have observable order. [Versioned catalog](https://raw.githubusercontent.com/sindresorhus/eslint-plugin-unicorn/v80.0.0/readme.md), [member order](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/consistent-class-member-order.md).

Opt-in rules such as `no-barrel-files`, `no-array-front-mutation`, `no-async-promise-finally`, `prefer-json-import`, `prefer-import-meta-properties`, `prefer-dispose`, `prefer-temporal`, `prefer-regexp-escape`, and the Uint8Array conversion rules do not currently create recommended-preset findings. Keep them disabled unless a separate requirement justifies enabling them. Package entry points, ordinary queues, awaited cleanup, fresh JSON reads, compatibility layers, and existing disposal contracts are common reasons not to impose those migrations globally. [Versioned catalog](https://raw.githubusercontent.com/sindresorhus/eslint-plugin-unicorn/v80.0.0/readme.md).

New built-ins need target verification. The Node version needed to run ESLint does not determine the browser or Node versions supported by the checked application. `no-unnecessary-polyfills` has target discovery/options, but that does not make every modern-API recommendation target-aware. Keep modern API rules as review findings and never accept an unsupported replacement. [Targets](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/v80.0.0/docs/rules/no-unnecessary-polyfills.md).

## Keep correctness checks

Retain rules about invalid Fetch/Response/Intl options, lost ArrayBuffer view boundaries, ignored lazy iterator results, invalid event removal, passive-listener cancellation, late DOM event access, invalid collection bracket access, unsafe property keys, imprecise JSON serialization, unsafe SQL interpolation, and escaped disposed resources. Ordinary syntax is not enough to justify these mistakes. If a specialized contract genuinely differs, review that concrete contract instead of disabling a whole correctness family. These categories and their active recommended membership come from the [versioned catalog](https://raw.githubusercontent.com/sindresorhus/eslint-plugin-unicorn/v80.0.0/readme.md).

## Recommendation

The framework-receiver, null-value, documentation-prefix, and narrowed arrow-function decisions are now applied. Ordinary function definitions remain subject to `consistent-function-scoping`. The remaining higher-priority candidates are `prefer-private-class-fields` for reactive models and `prefer-iterator-zip` for targets without that API; neither setting has been changed.

Keep `no-array-reduce`, `prefer-await`, `prefer-then-catch`, `prefer-event-target`, and coercion/DOM text rules in a second, contract-dependent group. Keep useful correctness rules. Do not switch wholesale to `unopinionated`: the current metadata comparison shows it omits 104 active recommended rules, including rules with meaningful correctness value.

Only explicitly authorized changes are applied. The maintained configuration remains the source of truth.
