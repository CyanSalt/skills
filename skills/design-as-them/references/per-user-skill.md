# Personalized skill structure

Create `design-as-me` in one user's isolated, explicitly selected location, or follow the
available skill-creation guidance's default when no location was chosen. Read an existing
skill before changing it; never borrow another user's preferences or overwrite silently.

## SKILL.md contract

- Frontmatter contains `name: design-as-me` and a concise third-person `description` with
  design/refinement triggers. Follow the target repository's language rules.
- The body contains the complete reusable design principles and personal preferences,
  with equal standing. References may supplement execution details, never hide operative
  preferences or constraints.
- Include only concise design application/check guidance. Critique collection, rule
  revision history, agent creation, context isolation, approval cycles, and cleanup belong
  to `design-as-them`, not the personalized skill.

With no feedback, state that taste is uncalibrated and leave the principles empty. Do not
use a different user's skill as a taste template or attribute generic design defaults to
this user.

## Principle quality

Each principle expresses a decision and meaningful conditions usable on a different
page. Keep supported quantitative constraints and role distinctions. Remove source-page
references and recipes that reveal a particular sample's expected answer. Merge related
feedback without weakening it. Necessary examples illustrate rather than define rules.
Verify factual claims separately from applying subjective preferences.

Check that a new designer can apply the body without prior pages or the original critique,
and that the update preserves established rules unless the user explicitly changes them.
Use pages without targeted comments to test transfer through the same general principles,
not extra page-specific design instructions.

## Final folder

Retain the required `SKILL.md` and only directly referenced resources that are genuinely
needed. Validate frontmatter, references, and any scripts. Freeze the user's explicitly
approved version; cleanup must not alter it or remove user-owned materials. Deliver the
ordinary folder/files, not an unsolicited package, and report verification limits.
